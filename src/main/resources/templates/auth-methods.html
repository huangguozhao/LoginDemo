🔍 认证方法技术对比

深入了解各种认证方案的优缺点

认证方法 优点 缺点 适用场景
Session-Based • 安全性高
• 服务器控制会话
• 支持复杂状态管理 		• 服务器存储压力
• 扩展性差
• CSRF风险 		企业级应用、复杂权限管理
OAuth2/OIDC • 标准化协议
• 支持第三方授权
• 良好的扩展性 		• 实现复杂度高
• 需要外部服务
• 协议复杂 		第三方登录、微服务架构
JWT Token • 无状态设计
• 良好的扩展性
• 支持跨域 		• 无法主动失效
• 令牌大小限制
• 安全性依赖算法 		API服务、移动应用、分布式系统
Apache Shiro • 功能丰富
• 易于集成
• 支持多种数据源 		• 学习曲线陡峭
• 配置复杂
• 社区活跃度一般 		Java企业应用、复杂安全需求

📋 技术实现要点

  • Session-Based: 使用Spring Security的默认会话管理，结合表单登录和会话存储
  • OAuth2/OIDC: 集成Spring Security OAuth2客户端，支持Google、GitHub等第三方登录
  • JWT Token: 自定义JWT过滤器，生成和验证JSON Web Token
  • Apache Shiro: 使用Shiro的Realm、Subject等核心组件实现认证和授权

🔧 演示说明

  • 所有认证方法都使用内存用户存储（无需数据库）
  • 演示用户：admin/admin123, user/user123
  • 每个方法都有独立的登录界面和受保护资源
  • 支持注销和会话管理功能
